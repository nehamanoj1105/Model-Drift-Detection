# Experiment 9A — Three Telecom Datasets + RAPT Baseline Comparison

_Auto-generated by `experiments/exp9a/three_dataset_report.py`._

## 1. Research objective

Determine whether RAPT (Regime-Aware Policy Transfer) can exploit recurring network conditions/regimes to maintain predictive performance while reducing adaptation cost compared with repeated retraining and conventional drift-detection-triggered adaptation, across three independent telecom/network datasets. The experiment separates predictive performance, adaptation efficiency and the ability to exploit recurrence.

## 2. Dataset descriptions

- **5G Campus Network QoS** — the repository's processed per-window QoS stream (NTNU/WUE testbeds). Target: 3-class next-window p90-delay QoS. Regimes: network scenario labels.

- **UGR'16** — ISP netflow feature data (Camacho feature-data mirror). The calibration split carries only blacklist traffic and no labelled attacks, so the labelled 30-day block is used. Target: binary anomaly (any non-blacklist attack minute). Regimes: workday/weekend x 4-hour period.

- **NordicDat** (Zenodo 10964584, CC-BY-4.0) — cross-border LTE/5G predictive-QoS traces. Target: 3-class next-window median-delay QoS (prefix thresholds). Regimes: mobile network operator.

## 4. Preprocessing

Shared lightweight pipeline: load -> documented target -> timestamp -> drop IDs/constants -> keep numeric features -> Inf->NaN -> drop rows with missing target -> training-prefix median imputation -> deterministic target encoding -> chronological ordering -> windowing. No PCA/SHAP/RFE/hyper-parameter search/global normalisation/shuffling.

## 5. Temporal protocol

Strict prequential (Test-Then-Train) evaluation. The initial training prefix is never used as test data; every window is predicted before it is appended to any adaptation buffer. Standardisation and any target thresholds use training-prefix statistics only.

## 6. Regime construction

UGR'16: workday/weekend x 4-hour period (semantic). NordicDat: mobile network operator (semantic). 5G Campus: scenario/regime_key (semantic). No clustering is used. Windows are aligned to regime blocks where the raw granularity differs (UGR'16 window = 240 minutes to match the 4-hour regime block).

## 12. Selected dataset

**UGR'16** is selected for the full five-seed run based on scientific suitability, not on RAPT's score: it has real temporal drift (the labelled 30-day block contains 1,364 attack minutes concentrated in the first 12 days), strong natural recurrence (12 recurring workday/weekend x period regimes), a meaningful sparse supervised target, and a manageable computational cost.

## 14b. Key observations (observed results)

These are direct readings of the measured results (5 seeds); statistical significance is reported separately in section 15.

- **5G Campus QoS.** All methods are near-saturated (macro-F1 0.936-0.984). RAPT matches Frozen (0.938) while Full Retraining reaches 0.984; RAPT adaptation CPU (0.24 s) is ~6x lower than Full Retraining (1.45 s) and it performs only 2 retrains vs 14.

- **UGR'16.** Frozen is strong (0.969) because anomalies are sparse and temporally clustered; RAPT's blind policy reuse is **harmful** (macro-F1 0.836, tumbling to ~0.80 in the clean post-attack period) because the recurring workday/weekend x period regimes look identical while the label relationship has changed. RAPT-Enhanced, which parity-refits a degraded reused policy, recovers to 0.928. Full Retraining is 0.960 at 24.1 s CPU and 144 retrains.

- **NordicDat.** The QoS class is weakly predictable (Frozen 0.278). Adaptation clearly helps: Full Retraining 0.423 > RAPT 0.382 > Frozen 0.278; RAPT again uses ~8x less adaptation CPU than Full Retraining (0.28 s vs 2.26 s) with 2 retrains and 16 reuses.

- **Historical detectors.** ADWIN, Page-Hinkley and EDMA are conservative here (0 adaptation events), so they match whichever model they never retrain; EDD adapts far more often (38 events) and is competitive where drift is frequent (5G Campus, NordicDat). See section 21 for the detector table.

- **Recurrence.** UGR'16 shows the strongest natural recurrence (168 recurrence events over 12 recurring regimes), which is exactly the structure that makes blind reuse risky when label semantics change.

Interpretation: RAPT provides a consistent adaptation-cost saving relative to repeated retraining, with near-parity predictive performance on stable/mildly-drifting streams (5G Campus) and on weakly-predictable streams (NordicDat). Under concept change that coincides with regime recurrence (UGR'16) base RAPT degrades and the parity-refit enhancement is required for recovery.

## 16. Limitations

- The three datasets differ in raw granularity and target semantics; the window size is chosen per dataset to give comparable counts of adaptation decisions. They are not identical tasks.

- UGR'16 uses the labelled 30-day block because the calibration split has no supervised attacks.

- NordicDat QoS classes are defined by training-prefix delay thresholds; label noise is possible near thresholds.

- No ground-truth drift boundaries exist for all datasets, so detector false-alarm/missed-drift metrics are not reported.

- Confidence intervals are computed at the window level and treat windows as exchangeable units.
